# Kernel v0.1 Freeze

Version: `0.1.0`

Purpose: declare which contracts are frozen enough to serve as the first stable product/kernel frame.

## Frozen contracts at v0.1
- `MandateSpec`
- `CampaignState`
- `PhaseMachine`
- `WorkerContextPack`
- `WorkerResult`
- `DeliveryPacket`
- `DomainAdapter`
- `WorkerStatePatch`
- `ReceiptRecord`
- `InitPolicy`
- `Dispatcher` responsibilities

## What “frozen” means here
- field names and conceptual boundaries should stop moving casually
- new work should prefer extension docs / adapter docs over mutating kernel nouns
- any kernel change should justify why the adapter boundary is insufficient

## What is still intentionally unfrozen
- exact runtime implementation
- CLI/tooling shapes under `tools/`
- how many helper docs/examples exist per adapter
- whether a thin OpenClaw operator skill is cut now or later

## Guardrails for future edits
Before changing a kernel contract, ask:
1. Is this actually a domain noun leaking upward?
2. Could this live in adapter metadata instead?
3. Does this make a non-Steamer adapter easier or harder?
4. Would a second adapter need the same kernel change?

If the answer to (2) is yes or (4) is no, the change probably does not belong in the kernel.

## First compatibility expectation
- Steamer adapter should remain compatible with `0.1.x`
- the next non-Steamer adapter should be able to map onto the same kernel without new trading-specific fields
