# Content-Production Adapter

Content production is the second adapter sketch for the framework.

## Why this adapter exists
Its job is to prove the kernel is not secretly a trading framework.

If the kernel can host:
- a Steamer strategy incubation campaign, and
- a content-production campaign

without changing kernel nouns, then the boundary is probably real.

## Domain nouns that stay in the adapter
- outline
- draft
- revision cycle
- publication-ready
- tone rubric
- scope violation
- publish approval

## Adapter responsibilities
- map publication intent into article/content campaign items
- define what counts as outline, draft, revision, hold, publish-ready
- classify authority boundaries (e.g. publish approval)
- package delivery in content/operator language

## Example use case
Mandate:
- "Produce a publication-ready long-form article positioning the framework for technical PMs and founding engineers."

Delivery:
- article packet
- artifact list
- confidence / caveats
- operator approval gate if publication authority is not autonomous
