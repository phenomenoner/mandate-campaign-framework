# Mandate Campaign Framework v0.1.0 (Experimental)

A schema-strict, phase-gated runtime for advanced OpenClaw campaigns.

## What this release is

This is the first public beta release of `mandate-campaign-framework`.
It packages the current framework into a dedicated public repo for advanced OpenClaw operators and workflow designers.

This release is for people who want:
- durable file-backed state
- explicit contracts
- bounded phase progression
- inspectable campaign flow
- operator-gated execution

It is **not** a beginner no-code builder and **not** a claim that generic adapter maturity is already fully proven.

## Included in v0.1.0

- campaign kernel docs and frozen v0.1 contracts
- runtime CLI:
  - `validate-mandate.py`
  - `init-campaign.py`
  - `advance-campaign.py`
  - `inspect-campaign.py`
- schema validation + tests for:
  - `CampaignState`
  - `WorkerStatePatch`
  - `ReceiptRecord`
- explicit phase transition semantics covering:
  - forward
  - retry
  - failure
  - back-transition
- reference adapter: `steamer`
- second adapter sketch: `content-production`
- seeded example campaign
- public-facing positioning and topology docs

## Why this matters

Most agent workflows still blur state, hide failure semantics, and make long-running progress hard to inspect. This framework takes the opposite approach:
- explicit state
- explicit receipts
- explicit transitions
- bounded worker progression
- operator visibility

## Current limits

Today this repo still assumes an advanced operator posture:
- campaigns advance step-by-step via CLI
- worker dispatch remains intentionally thin
- adapter genericity is still being proved
- public ergonomics are still early
